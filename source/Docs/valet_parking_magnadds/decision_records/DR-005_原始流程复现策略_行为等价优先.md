# DR-005：原始流程复现策略采用行为等价优先

- 日期：2026-07-28
- 状态：ACTIVE
- 关联文档：`../05_TempAPA原始流程复现差距对照表.md`

## 背景

用户询问当前 DDS Adapter 是否能完美复现 `E:\APA\DDS\TempAPA_Code` 中 `ValetParkingStageParking` 的泊车入位逻辑流程和细节。

对照原始 `00_ValetParkingStageParking_超详细流程图总览_重要.md` 和源码后可以确认：原始流程不只是 `ROI_DECIDER -> PATH_PROVIDER -> PATH_PARTITION -> SPEED_OPTIMIZER` 四个任务顺序执行，还包含 Stage 状态机、FunctionManager 输入、Frame/OpenSpaceInfo、OpenSpacePathProvider 线程管理、NLP smoother、DIRECT 直行分支、HMI/parking_status 收口等框架级行为。

## 决策

当前 MagnaDDS 适配不以“逐行复制 TempAPA_Code”作为目标。

后续采用：

```text
行为等价优先；
结构适配 MagnaDDS；
差异文档化；
每个补齐点都用 smoke 或静态验证收口。
```

## 理由

逐行复制原始工程会把以下依赖直接带入当前 DDS MVP：

- 完整 `Frame`
- 完整 `DependencyInjector`
- 完整 `PlanningContext`
- 大量 protobuf 生成文件
- 原车配置系统
- OpenSpaceThreadManager 多线程状态
- NLP smoother 及其第三方依赖

这会明显扩大当前 `.so + typed DDS` 的范围，并破坏现有 `Component -> Adapter -> 本地算法源码` 的清晰分层。

更稳妥的方式是：先保持当前已验证主链路，再按原始流程差距表逐项补行为。

## 影响

后续不能把当前状态描述为“完美复现原始 TempAPA_Code”。

可以描述为：

```text
已复现普通 open space 主链路的核心算法流程；
Stage/Frame/PathProvider 大框架仍在差距清单中逐步补齐。
```

近期优先补：

1. 多车位 `opt_parking_seq` 行为验证。
2. 轻量 Stage 控制输入设计。
3. `DIRECT_FORWARD/DIRECT_BACKWARD` 直行分支。
4. pause/brake/finish 行为等价 smoke。

完整 `OpenSpacePathProvider` 大类、线程管理和 NLP smoother 必须单独评估，不作为顺手改动混入。
