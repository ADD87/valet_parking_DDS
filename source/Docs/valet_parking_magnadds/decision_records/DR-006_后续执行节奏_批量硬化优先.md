# DR-006 后续执行节奏：批量硬化优先

日期：2026-07-29

## 背景

NEXT-039 到 NEXT-041 已把 direct 分支、OpenSpacePathProvider 线程体系、线程生命周期和 timeout 负向路径跑通。继续按单个 NEXT 小步推进，会反复经历“改一点、编译一次、smoke 一次、再改一点”的低效循环。

当前主链路已有一定稳定性：

```text
SelectedSlot -> ROI_DECIDER -> PATH_PROVIDER -> PATH_PARTITION -> SPEED_OPTIMIZER
ParkingCommand DIRECT_* -> OPEN_SPACE_STRAIGHT_PATH -> SPEED_OPTIMIZER
```

因此后续更适合批量扫描、批量修订，再统一验证。

## 决策

从 NEXT-042 开始，后续节奏切换为：

```text
先批量检测和契约扫描
-> 再批量修订代码/脚本/文档
-> 再统一 x86/m57 编译
-> 再统一 x86 smoke 矩阵
-> 再集中排错
-> 再更新文档并提交推送
```

NEXT-042 到 NEXT-046 合并为 `BATCH-042_046`：

```text
direct 分支输出契约补强
ParkingCommand 生命周期硬化
PAUSE/BRAKE/FINISH 与原 Stage 差距收敛
PARKING_OUT_* MVP 行为定义
主链路 Stage 状态输出增强
```

## 边界

本决策不改变以下硬边界：

```text
不修改 compile/
不修改 thirdparty/
不扩大临时 IDL 字段
不把 replan_reason/estop.reason 文本诊断说成正式 DDS 字段
不把 m57 交叉编译说成板端运行通过
不全量复制外部 parking_algorithm_standalone 或 Repair_... 目录
```

## 验收方式

`BATCH-042_046` 完成时至少需要：

```text
x86 build PASS
m57 build PASS
m57 ELF/NEEDED/RPATH 检查 PASS
x86 valid parking-in smoke PASS
x86 timeout fallback smoke PASS
x86 multi-lot PrePlan smoke PASS
x86 direct-forward/direct-backward smoke PASS
x86 pause/brake/finish/invalid smoke PASS
x86 reset_history / command clear smoke PASS
x86 parking-out unsupported smoke PASS
必要的 obstacle / target / path_id 核心回归 smoke PASS
```

如果批量 smoke 中出现失败，先按失败类型集中归类，再批量修订，不再每个 NEXT 单独碎片化排错。
