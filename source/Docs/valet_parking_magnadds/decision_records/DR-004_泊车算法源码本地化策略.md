# DR-004：泊车算法源码本地化策略

- 决策编号：DR-004
- 日期：2026-07-27
- 状态：ACTIVE
- 关联阶段：NEXT-032 - 泊车算法源码本地化

---

## 1. 背景

当前 `valet_parking` 模块已经完成并验证了 MVP 主链路：

`SelectedSlot -> ROI_DECIDER -> PATH_PROVIDER -> PATH_PARTITION -> SPEED_OPTIMIZER -> PlanningTrajectory`

但是 `applications/source/valet_parking/CMakeLists.txt` 仍通过外部路径引用：

`E:\APA\DDS\parking_algorithm_standalone`

这意味着 `applications` Git 仓库还不是完全自包含的 MagnaDDS 泊车适配工程。换机、交接或 CI 构建时，只拿到 `applications` 目录仍无法保证可构建。

---

## 2. 决策内容

NEXT-032 将执行“泊车算法源码本地化”：

1. 在 `applications/source/valet_parking/algorithm/parking_algorithm_standalone` 下放置当前已验证链路实际使用的算法源码。
2. 迁移范围以当前 `valet_parking/CMakeLists.txt` 中列出的源文件为起点。
3. 只复制这些源文件所需的头文件依赖和最小目录结构。
4. 修改 `valet_parking/CMakeLists.txt`，优先使用本地相对路径。
5. 完成后，`applications` 不再依赖 `E:\APA\DDS\parking_algorithm_standalone` 这个外部绝对路径即可构建当前 MVP。
6. 本地化后必须通过 x86 构建、核心 smoke 回归和 m57 交叉编译。

---

## 3. 迁移范围

当前已知必须覆盖的源码类别：

- `common/math/**` 中已被 CMake 编译的几何、路径和插值源文件。
- `common/configs/vehicle_config_helper_simple.*`。
- `planning/tasks/deciders/open_space_decider/**` 中 ROI 相关源文件。
- `planning/open_space/coarse_path_generator/**` 中 Hybrid A* 粗路径相关源文件。
- `planning/tasks/optimizers/open_space_path_generation/**`。
- `planning/tasks/optimizers/open_space_path_partition/**`。
- `planning/tasks/optimizers/open_space_speed_optimizer/**`。
- `planning/common/path/**`、`planning/common/speed/**`、`planning/common/trajectory/**`、`planning/common/trajectory1d/**` 中当前链路使用的最小源码和头文件。

---

## 4. 禁止范围

本地化不是全量复制 standalone。以下内容不得进入产品构建链路：

- `parking_algorithm_standalone` 整个目录的无筛选复制。
- `proto/**/*.pb.*`。
- ROS2 节点、launch、demo、test out 或历史构建产物。
- 未经确认的 IPOPT/glog/gflags/Abseil 等外部依赖代码。
- 完整 `Frame/DependencyInjector`、完整 Stage 状态机、完整线程管理或 NLP smoother。
- 对 `E:\APA\DDS\parking_algorithm_standalone` 原始参考目录的修改。

---

## 5. 为什么这样决定

| 原因 | 说明 |
|---|---|
| 提高可交接性 | `applications` Git 仓库应包含当前 MVP 构建所需源码 |
| 降低换机风险 | 不再要求新电脑存在外部 `parking_algorithm_standalone` 绝对路径 |
| 保持可控范围 | 只迁移当前已验证链路，避免重新打开完整原车依赖 |
| 保留验证闭环 | 每次迁移后仍用 x86 smoke 和 m57 交叉编译证明行为未破坏 |

---

## 6. 被拒绝的替代方案

### 6.1 继续长期依赖外部 standalone 路径

拒绝原因：

- 交接不完整。
- 换机后容易丢路径或版本不一致。
- `applications` Git 无法独立说明当前算法源码基线。

### 6.2 一次性复制整个 standalone 目录

拒绝原因：

- 会引入无关 ROS2、proto、demo、out 和历史产物。
- 会让 Git 噪声很大，后续 review 困难。
- 容易把未验证依赖带进产品构建链路。

### 6.3 直接迁移完整 OpenSpacePathProvider 大类

拒绝原因：

- 当前目标是解除源码外部路径依赖，不是扩大算法功能。
- 完整大类会重新引入线程管理、Frame/DependencyInjector、NLP smoother 等未验证依赖。

---

## 7. 验收标准

NEXT-032 完成时必须满足：

1. `valet_parking/CMakeLists.txt` 不再引用 `E:\APA\DDS\parking_algorithm_standalone` 或等价外部绝对路径。
2. 当前 MVP 所需算法源码位于 `applications/source/valet_parking/algorithm/parking_algorithm_standalone`。
3. x86 构建通过。
4. x86 至少通过默认 valid smoke、`parking-seq-changes` 或 `target-moves` 核心回归、all-valid 辅助输入回归。
5. m57 交叉编译通过并生成 ARM aarch64 `libvalet_parking.so`。
6. m57 板端运行仍按实际情况记录；无板端时不得写成通过。
