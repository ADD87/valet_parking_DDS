# DR-000：初始范围锁定

- 决策编号：DR-000
- 日期：2026-07-26
- 状态：ACTIVE
- 关联阶段：Phase 0 — 文档计划与基线冻结

---

## 1. 背景

用户希望将原始 APA 工程中的泊车入位 `ValetParkingStageParking` 相关代码，逐步适配到当前 `feature_integration_workspace`，使用当前工程的 MagnaDDS 中间件。

已知情况：

1. 原始代码位于 `TempAPA_Code`，强依赖完整工程、Proto、common、map 等模块。
2. 之前已有 standalone ROS2 版本 `parking_algorithm_standalone`，其中 planning 和 proto_convert 有一定复用价值，但也存在错误和依赖风险。
3. 当前工程要求优先实现基于 MagnaDDS 的 `.so`，未实现 Topic 先用自定义版本。
4. 当前 Thirdparty 中已有部分第三方库，正式版本不应随意引入外部依赖。
5. 当前无 m57 板端，无法真实完成板端 DDS runtime 验证。

---

## 2. 决策内容

首版 MVP 范围锁定为：

1. 先创建本地 `Doc/valet_parking_magnadds` 文档体系。
2. 用户确认计划前，不创建业务源码模块。
3. 首版只做 MagnaDDS 通信骨架和 m57 可编译 `.so`。
4. 首版产物名目标为 `libvalet_parking.so`。
5. 输入 Topic 使用 `/selected_slot`，结构尽量完整镜像原始 `ParkingLotOutArray`，但数据可由 mock publisher 造一个假车位。
6. 输出 Topic 使用 `/planning/trajectory`，只保留轨迹相关字段，尽量保持原始 `ADCTrajectory` 轨迹元素一致。
7. 首版规划器使用 `FakeParkingPlanner`，输出确定性假轨迹。
8. 不在首版接入完整 Hybrid A*、NLP、SpeedOptimizer 或原始 Stage 状态机。
9. 只使用 workspace `thirdparty` 中已有的 MagnaDDS 库；官方 SDK 仅用于 IDL 生成和 API 参考。
10. 不修改 `compile/` 和 `thirdparty/` 绕过问题。
11. 无 m57 板端时，DDS runtime 状态必须写为 `BLOCKED_NO_M57_BOARD`。

---

## 3. 为什么这样决定

| 原因 | 说明 |
|---|---|
| 降低首版风险 | 先证明 MagnaDDS、构建、`.so`、Topic 框架通，再逐步接算法 |
| 满足领导优先级 | 领导明确要求优先实现 MagnaDDS 的 bin/`.so` 生成 |
| 保护 Topic 契约 | 输入输出结构先稳定，后续真实算法接入不需要推翻通信层 |
| 避免依赖爆炸 | standalone 和原始工程依赖复杂，不适合第一步全量搬迁 |
| 便于交接 | 文档、状态快照、决策记录可让后续 AI 继续执行 |

---

## 4. 被拒绝的替代方案

### 4.1 直接复制 standalone planning 代码

拒绝原因：

- standalone 中的 Protobuf 生成代码版本可能与当前 Thirdparty 不兼容。
- 可能依赖 IPOPT/glog/gflags/Abseil 等当前工程未正式集成的库。
- 之前改造本身可能存在错误，不能作为可信源码原样复制。
- 会在 MagnaDDS 通信层未稳定前引入过多变量。

### 4.2 先做完整原始 Stage 迁移

拒绝原因：

- 原始 Stage 强依赖车辆状态、定位、底盘、障碍物、Freespace、routing/command 等输入。
- 当前用户希望输入可以先简化。
- 完整迁移会掩盖当前最关键目标：MagnaDDS `.so` 骨架可编译可交付。

### 4.3 用 ROS2/SOA-DDS/CycloneDDS 替代 MagnaDDS

拒绝原因：

- 用户和领导明确要求当前工程中间件 MagnaDDS。
- 其他 DDS 栈即使跑通，也不能作为本任务验收。

### 4.4 把 SDK demo 或 SDK `.so` 直接打进产品

拒绝原因：

- 领导要求 Thirdparty 中已有的优先使用 Thirdparty。
- 产品必须链接当前 workspace 的 Thirdparty，SDK 仅用于生成和参考。
- 混用库可能产生 ABI 和板端部署风险。

---

## 5. 影响范围

| 影响对象 | 影响 |
|---|---|
| 计划 | 首版变成“真实 MagnaDDS 骨架 + 假算法” |
| Topic | 输入输出契约先冻结，数据可 mock |
| 构建 | 先只做 m57，不做 x86 正式产物 |
| 算法 | 完整算法迁移推迟到后续 Phase 8 |
| 文档 | 每阶段必须输出状态快照和必要决策记录 |

---

## 6. 回滚或重新评估条件

出现以下情况时，需要新增决策记录重新评估：

1. 领导要求首版必须接真实算法，而不是 fake planner。
2. m57 工具链或 Thirdparty MagnaDDS 不可用，导致 `.so` 无法编译。
3. MagnaDDS IDL parser 无法表达必要 Topic 结构。
4. 用户要求首版改为 x86 或双平台。
5. 正式工程要求 Topic 必须完全等价原始 Protobuf，而不是首版 allowlist。
6. Thirdparty 被正式补齐 IPOPT/glog/gflags/Abseil，并要求提前迁移算法。

---

## 7. 当前结论

本决策生效。后续任何 AI 或开发者不得在没有新决策记录的情况下扩大首版范围。
