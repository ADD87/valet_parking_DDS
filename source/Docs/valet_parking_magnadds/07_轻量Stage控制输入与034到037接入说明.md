# 轻量 Stage 控制输入与 NEXT-034 到 NEXT-037 接入说明

本文记录 NEXT-034 到 NEXT-037 的代码意图：在当前 `ValetParkingStageParking` MagnaDDS MVP 中新增一个独立的 `ParkingCommand` DDS Topic，用来表达原始 Stage 中能观察到的控制语义，例如直行、暂停、刹停和完成。

这不是完整 `FunctionManager`，也不是完整 `OpenSpaceStraightPathProvider`。当前阶段先做可验证的轻量闭环，让 DDS 输入可以控制 Adapter 在进入 ROI/PATH_PROVIDER 主链路前切到对应分支。

> NEXT-038 已将 direct 分支升级为本地化 `OPEN_SPACE_STRAIGHT_PATH -> SPEED_OPTIMIZER -> PlanningTrajectory`。本文件仍保留 NEXT-034 到 NEXT-037 的历史说明；direct 分支当前真实链路请看 `08_完整OpenSpaceStraightPathProvider与038接入说明.md`。

---

## 1. 为什么要新增 ParkingCommand

原来当前工程只有一个主输入：

```text
/selected_slot
```

它表达“用户选了哪个车位”。这适合触发泊车入位主链路：

```text
SelectedSlot
-> ROI_DECIDER
-> PATH_PROVIDER
-> PATH_PARTITION
-> SPEED_OPTIMIZER
-> PlanningTrajectory
```

但原始泊车 Stage 不只会“入位规划”。它还会遇到：

- 直行向前
- 直行向后
- 暂停
- 刹停
- 泊车完成
- 泊出方向

这些不是车位本身的属性。如果把它们硬塞进 `SelectedSlot.is_valid` 或 `opt_parking_seq`，字段语义会变脏，后面接真实车端协议时更难对齐。

所以新增：

```text
/parking/command
```

它表达“当前 Stage 希望怎么运行”。

## 2. IDL 新增内容

文件：

```text
applications/source/valet_parking/idl/valet_parking_topics.idl
```

新增 enum：

```text
ParkingCommandMode
```

主要取值：

| 模式 | 当前行为 |
|---|---|
| `PARKING_COMMAND_NONE` | 清空命令缓存，继续普通泊车入位 |
| `PARKING_COMMAND_PARKING_IN` | 继续普通泊车入位，可配合 `reset_history` 清一次历史 |
| `PARKING_COMMAND_DIRECT_FORWARD` | 跳过 ROI/PATH_PROVIDER/PATH_PARTITION，生成轻量前进直线轨迹 |
| `PARKING_COMMAND_DIRECT_BACKWARD` | 跳过 ROI/PATH_PROVIDER/PATH_PARTITION，生成轻量倒车直线轨迹 |
| `PARKING_COMMAND_PAUSE` | 输出非 estop 的单点停止轨迹 |
| `PARKING_COMMAND_BRAKE` | 输出非 estop 的单点停止轨迹 |
| `PARKING_COMMAND_FINISH` | 输出非 estop 的单点停止轨迹，原因中带 `MISSIONFINISHED` |
| `PARKING_COMMAND_PARKING_OUT_*` | 当前 MVP 只输出安全停止，标记 `unsupported_in_mvp` |

新增 struct：

```text
ParkingCommand
```

字段含义：

| 字段 | 像孩子一样解释 |
|---|---|
| `header` | 这张“小纸条”的编号和时间 |
| `is_valid` | 这张命令纸条能不能信 |
| `mode` | 想让泊车 Stage 做什么 |
| `parking_seq` | 命令关联的车位编号，可选 |
| `direct_distance_m` | 直行分支走多远 |
| `direct_speed_mps` | 直行分支用多快 |
| `reset_history` | 是否把上一帧路径/速度历史清一次 |
| `reason` | 人能看懂的命令原因 |

修改 IDL 后，已用 MagnaDDS SDK `idlparser` 重新生成：

## 3. Component 怎么处理 command

文件：

```text
applications/source/valet_parking/src/valet_parking_component.cpp
```

新增默认 topic：

```text
/parking/command
```

runner 默认订阅它。也可以关闭：

```bash
valet_parking_runner --disable-command-topic
```

Component 的职责很简单：

```text
收到 ParkingCommand
-> 检查 is_valid、mode、direct 参数是否合理
-> 保存为 latest command
-> 下一条 SelectedSlot 进来时，把 latest command 一起交给 Adapter
```

它不是每条 command 都立刻规划。当前主触发仍是 `SelectedSlot`，command 更像一张贴在桌上的“当前模式小纸条”。

## 4. Adapter 怎么分支

文件：

```text
applications/source/valet_parking/src/valet_parking_stage_parking_adapter.cpp
```

Adapter 在进入普通主链路前先看 command：

```text
如果 command 是 DIRECT_FORWARD / DIRECT_BACKWARD
  -> 直接生成轻量直线轨迹
  -> 不跑 ROI_DECIDER
  -> 不跑 PATH_PROVIDER
  -> 不跑 PATH_PARTITION

如果 command 是 PAUSE / BRAKE / FINISH
  -> 直接生成单点停止轨迹
  -> estop=false

如果 command 是 PARKING_IN 或没有 command
  -> 继续原来的泊车入位主链路
```

直行分支输出原因里会包含：

```text
STAGE_CONTROL DIRECT_FORWARD, skip=ROI_PATH_PROVIDER_PATH_PARTITION
STAGE_CONTROL DIRECT_BACKWARD, skip=ROI_PATH_PROVIDER_PATH_PARTITION
```

暂停、刹停、完成分支输出原因里会包含：

```text
STAGE_CONTROL PAUSE
STAGE_CONTROL BRAKE
STAGE_CONTROL FINISH, MISSIONFINISHED
```

这样 smoke 可以从 runner/subscriber 日志里直接确认分支走对了。

## 5. 新增 mock publisher

新增目录：

```text
applications/source/valet_parking_tools/parking_command_mock_publisher
```

它只做一件事：发布 `ParkingCommand` typed DDS 样本。

常用命令：

```bash
parking_command_mock_publisher --domain-id=230 --mode=direct-forward
parking_command_mock_publisher --domain-id=231 --mode=direct-backward
parking_command_mock_publisher --domain-id=232 --mode=pause
parking_command_mock_publisher --domain-id=233 --mode=brake
parking_command_mock_publisher --domain-id=234 --mode=finish
```

它已加入：

```text
applications/config/valet_parking_mvp_bom.yaml
```

所以快捷构建会一起产出这个工具。

## 6. smoke 脚本新增参数

文件：

```text
applications/source/valet_parking_tools/smoke_valet_parking_x86.sh
```

新增：

```bash
--command-mode direct-forward
--command-mode direct-backward
--command-mode pause
--command-mode brake
--command-mode finish
```

示例：

```bash
bash applications/source/valet_parking_tools/smoke_valet_parking_x86.sh \
  --run-root /mnt/e/APA/DDS/feature_integration/feature_integration_workspace/out/valet_parking_stage_command_037/valet_parking_mvp/x86 \
  --domain-id 230 \
  --command-mode direct-forward
```

脚本会按这个顺序启动：

```text
runner
-> subscriber
-> parking_command_mock_publisher
-> selected_slot_mock_publisher
```

这样 command 会先进入 Component 缓存，SelectedSlot 到达时触发对应分支。

## 7. 当前边界

本阶段完成的是“轻量 Stage 控制闭环”，不是完整泊车出入库状态机。

明确没有做：

- 完整 `FunctionManager`
- 完整 `OpenSpaceStraightPathProvider`
- 完整泊出逻辑
- 完整原车 `Stage/Frame/DependencyInjector`
- NLP smoother
- 真实车端 command Topic 协议对齐
- m57 板端运行验证

后续如果要把 direct 分支从“轻量直线轨迹”升级为完整原车 `OPEN_SPACE_STRAIGHT_PATH`，应先补齐本地算法源码和输入输出契约，再替换当前 `BuildDirectTrajectory()`。
