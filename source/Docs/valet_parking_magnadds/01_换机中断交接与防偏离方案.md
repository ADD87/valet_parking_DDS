# 换机 / 中断后 AI 无缝交接与防偏离方案

- 项目：ValetParkingStageParking MagnaDDS MVP
- 目录：`Doc/valet_parking_magnadds`
- 原则：**状态必须沉淀到本地文档，不依赖聊天记录。**

---

## 1. 为什么必须先做文档交接体系

本项目同时涉及：

1. 原始 APA 工程代码。
2. standalone ROS2 改造代码。
3. 当前 feature_integration 中间件工程。
4. MagnaDDS SDK 和 Thirdparty。
5. m57 交叉编译和后续板端验证。

如果只靠聊天记录，后续非常容易出现：

- 换电脑后不知道上次做到哪一步。
- 换 AI 后重新推翻已经确认的方案。
- 为了编译通过偷偷删 Topic 字段。
- 把 SDK demo 成功误认为产品成功。
- 把无板端运行写成已通过。

因此，后续所有状态都以本目录中的文件为准。

---

## 2. 单一事实来源

后续接手时，按以下优先级读取：

| 优先级 | 文件/目录 | 作用 |
|---:|---|---|
| 1 | `STATUS.yaml` | 当前阶段、状态、唯一下一步、阻塞项 |
| 2 | 最新 `status_snapshots/xxx_项目状态快照_*.md` | 最近完成阶段的详细状态 |
| 3 | `00_执行计划书_ValetParkingStageParking_MagnaDDS.md` | 总计划和阶段门禁 |
| 4 | `decision_records/` | 所有偏离原计划或关键技术选择的原因 |
| 5 | 构建/验证日志 | 命令证据和失败现场 |

聊天记录只能作为补充，不能覆盖上述文件。

---

## 3. AI 接手固定流程

每次换电脑、换 AI、或长时间中断后恢复，必须按这个顺序执行：

1. 打开 `Doc/valet_parking_magnadds/README.md`。
2. 读取 `STATUS.yaml`。
3. 读取最新一份 `status_snapshots/xxx_项目状态快照_*.md`。
4. 读取 `decision_records/` 中最新决策。
5. 明确当前 `current_phase` 和唯一 `next_action`。
6. 只执行 `next_action`，不要跳到后续阶段。
7. 如果发现状态文件和实际代码不一致，先新增状态快照记录矛盾，不要直接改代码。
8. 阶段完成后输出新的带序号状态快照。

## 4. 防止执行偏离的规则

### 4.1 阶段验收制

每个阶段都有明确门禁：

- 阶段开始前：确认输入齐全。
- 阶段执行中：只做本阶段任务。
- 阶段完成后：对照验收标准逐项检查。
- 验收未通过：不得进入下一阶段。
- 验收通过：更新 `STATUS.yaml` 和状态快照。

示例：

- Phase 2 没冻结 Topic 契约，就不能进入 `.so` 开发。
- Phase 3 没验证 IDL 生成，就不能写 DDS 收发。
- Phase 6 没完成 m57 静态验收，就不能声称交付完成。

### 4.2 决策留痕制

以下情况必须新增 `decision_records/DR-xxx_*.md`：

1. 与原计划不一致。
2. 改 Topic 字段、枚举、单位、默认值。
3. 增加、删除或替换第三方依赖。
4. 修改 `compile/` 或 `thirdparty/` 的想法，即使最后没改也要记录原因。
5. 由于工具限制调整 IDL 表达方式。
6. 将某项从首版移到后续，或从后续提前到首版。
7. 任何会影响后续算法迁移的设计选择。

决策记录必须包含：

- 背景。
- 原计划。
- 新决定。
- 为什么要改。
- 替代方案为什么不选。
- 影响范围。
- 回滚条件。

### 4.3 范围锁死制

每次给 AI 的需求开头建议加：

> 严格按既定计划执行，不做计划外的功能扩展，遇到方案变更先说明原因并写入决策记录。

当前首版范围锁死为：

- 只做 MagnaDDS 骨架。
- 只做 m57。
- 只做 fake parking planner。
- 输入 `/selected_slot` 可 mock。
- 输出 `/planning/trajectory` 保持轨迹字段一致性。
- 不接完整算法。
- 不改 `compile/` 和 `thirdparty/`。
- 不把无板端运行写成通过。

### 4.4 单一下一步制

`STATUS.yaml` 中只能有一个 `next_action`。

不允许写成：

- “继续开发”。
- “完善代码”。
- “看情况处理”。

必须写成：

- “等待用户确认 Phase 0 计划文档”。
- “执行 Phase 1：记录四个子仓 git 状态和工具链可用性”。
- “修复 Phase 3 IDL parser 对 sequence 的生成问题”。

### 4.5 禁止动作清单

- 禁止绕过当前阶段验收。
- 禁止在没有决策记录的情况下改 Topic 契约。
- 禁止为了编译通过删字段。
- 禁止把 SDK demo 当产品验证。
- 禁止把 x86 历史产物当 m57 成功。
- 禁止把板端未测写成已通过。
- 禁止把聊天里的口头结论当最终状态。
- 禁止一次性大规模复制 standalone 规划代码。

## 5. 状态快照制度

### 5.1 什么时候必须输出状态快照

以下情况必须创建新的 `status_snapshots/xxx_项目状态快照_*.md`：

1. 每个阶段完成时。
2. 即将暂停工作时。
3. 运行卡住且需要交接时。
4. 关键 blocker 出现时。
5. 用户要求检查进度时。
6. 发生计划变更时。

### 5.2 编号规则

建议格式：

```text
status_snapshots/
  000_项目状态快照_计划文档创建.md
  001_项目状态快照_基线环境审计.md
  002_项目状态快照_Topic契约冻结.md
  003_项目状态快照_IDL生成验证.md
  004_项目状态快照_SO骨架实现.md
  005_项目状态快照_DDS收发FakePlanner.md
  006_项目状态快照_m57构建打包.md
  007_项目状态快照_交付归档.md
```

如果某阶段失败或卡住，可以追加：

```text
003A_项目状态快照_IDL生成卡住.md
003B_项目状态快照_IDL生成修复后.md
```

### 5.3 快照必须包含

- 快照编号。
- 日期。
- 当前阶段。
- 阶段状态：未开始 / 进行中 / 已完成 / 阻塞。
- 本阶段目标。
- 已完成事项。
- 未完成事项。
- 当前 blocker。
- 最近执行命令或动作。
- 产物路径。
- 修改文件列表。
- 验收标准逐项状态。
- 决策记录链接。
- 下一步唯一动作。
- 明确禁止动作。

## 6. 决策记录制度

### 6.1 编号规则

```text
decision_records/
  DR-000_初始范围锁定.md
  DR-001_IDL字段映射调整.md
  DR-002_MagnaDDS生成器限制处理.md
```

### 6.2 决策记录必须回答

1. 为什么做这个决定？
2. 不这么做有什么问题？
3. 对当前阶段有什么影响？
4. 对后续真实算法迁移有什么影响？
5. 什么时候需要重新评估？

---

## 7. 运行卡住时的处理流程

### 7.1 通用流程

1. 不要继续扩大改动。
2. 保存当前错误日志。
3. 判断卡住类型。
4. 更新 `STATUS.yaml` 的 `blockers`。
5. 创建临时状态快照，例如 `003A_项目状态快照_IDL生成卡住.md`。
6. 若需要变更方案，先写决策记录。
7. 只修一个根因。
8. 修复后再输出下一份状态快照。

### 7.2 卡住分类表

| 卡住位置 | 优先看什么 | 输出什么状态 |
|---|---|---|
| IDL 生成 | parser 路径、IDL 语法、SDK 版本、最小 demo | `IDL_GENERATION_BLOCKED` |
| CMake 配置 | module 名、target 名、BOM、include 路径 | `CMAKE_CONFIG_BLOCKED` |
| 编译 | 第一条 error、告警是否被 `-Werror` 放大 | `COMPILE_BLOCKED` |
| 链接 | AArch64 库、MagnaDDS target、未定义符号 | `LINK_BLOCKED` |
| 打包 | install 规则、BOM、输出路径 | `PACKAGE_BLOCKED` |
| 板端运行 | m57 板、库路径、Topic、Domain、QoS | `RUNTIME_BLOCKED` 或 `BLOCKED_NO_M57_BOARD` |

## 8. `STATUS.yaml` 维护规则

`STATUS.yaml` 是当前状态入口，必须保持简洁。

必须包含：

- `project`。
- `current_phase`。
- `phase_status`。
- `last_completed_snapshot`。
- `last_successful_action`。
- `blockers`。
- `next_action`。
- `allowed_scope`。
- `forbidden_actions`。
- `runtime_status`。
- `decision_records`。

每次阶段结束、卡住、恢复，都要更新。

## 9. 推荐给 AI 的提示词模板

### 9.1 正常继续执行

> 严格按既定计划执行，不做计划外的功能扩展，遇到方案变更先说明原因并写入决策记录。请先读取 `Doc/valet_parking_magnadds/STATUS.yaml`、最新项目状态快照和执行计划书，只执行 `next_action`，完成后输出新的带序号状态快照。

### 9.2 卡住后排查

> 严格按既定计划排查，不扩大改动范围。请先读取 `STATUS.yaml` 和最新状态快照，判断当前卡住类型，只定位一个根因；如果需要改变原计划，先创建决策记录，再修改代码或文档。

### 9.3 阶段验收

> 严格按执行计划书中当前阶段的验收标准逐项检查，不得提前进入下一阶段。请输出验收结果、未通过项、blocker、下一步，并更新本地状态快照。

## 10. 当前适用结论

当前项目处于 Phase 0：文档计划创建阶段。

当前唯一下一步应是：

> 用户审阅并确认《执行计划书》和《换机中断交接与防偏离方案》；确认后进入 Phase 1：代码库基线与环境审计。

在用户确认前，不应开始业务代码实现。
