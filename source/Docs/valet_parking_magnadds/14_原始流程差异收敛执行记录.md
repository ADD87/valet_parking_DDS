## BATCH-049_052 收敛目标

本批次选择原始流程图里的“Stage 对外状态翻译与覆写链”作为收敛切口。

原始流程重点：

```text
Stage::ExecuteTaskOnOpenSpace()
  -> publishable_trajectory_data = speed_optimizer_trajectory
  -> frame.target_gear = speed_optimizer_trajectory.second

ValetParkingStageParking::Process()
  -> speed_task_interactive_stage 翻译为 WAITOBSTACLE / RUNNING
  -> IsReadyToFinishStage() 成立时覆写为 MISSIONFINISHED / PARKINGFINISHED
```

本批次当前实现：

```text
PATH_PARTITION ok
  -> decision_name
  -> finish_name
  -> destination_reached

SPEED_OPTIMIZER ok
  -> stage_name

STAGE_OUTPUT open_space
  -> stage_status
  -> task_chain
  -> path_decision
  -> finish_status
  -> destination_reached
  -> target_gear
  -> trajectory_type
  -> parking_status
  -> speed_interactive_stage
  -> finish_priority=finish_over_interactive
```

这不是把原始 `Frame/FunctionManager/HMI` 全部搬过来，而是在当前 DDS MVP 内先建立行为等价的输出收口契约。这样可以继续复用当前已经跑通的主链：

```text
SelectedSlot -> ROI_DECIDER -> PATH_PROVIDER -> PATH_PARTITION -> SPEED_OPTIMIZER -> PlanningTrajectory
```

## 已减少的差异

| 原始流程节点 | 之前差异 | 本批次收敛 |
|---|---|---|
| `OpenSpacePathPartition::Process` | 只看数字 decision/finish，不利于对照流程图 | 增加 `decision_name/finish_name/destination_reached` |
| `OpenSpaceSpeedOptimizer::Process` | 只输出 `stage=<number>` | 增加 `stage_name=INIT/RUNNING/WAITOBSTACLE/WAITREPLAN` |
| `Stage::ExecuteTaskOnOpenSpace` 发布收口 | 当前 Adapter 只拼接各 task reason，没有统一 Stage 输出层 | 增加 `STAGE_OUTPUT open_space` |
| `target_gear` | 轨迹里有 gear，但 reason 里没有按 Stage 语义集中表达 | `STAGE_OUTPUT` 写入 `target_gear` |
| `parking_status` | 只在 direct/pause/finish 等控制分支较清楚，普通主链缺少统一翻译 | 普通主链根据 finish/status/interactive stage 生成 `parking_status` |
| finish 优先级 | 未表达“finish 覆写 interactive stage” | `STAGE_OUTPUT` 写入 `finish_priority=finish_over_interactive` |

## BATCH-053_056 收敛目标

本批次继续对照原始流程图，不转向外围问题。切口是下面三段：

```text
[I] Stage 收口与 finish 判定
[A3] FunctionManager/sys_command -> parking_type 判型
[C/D] ROI -> OpenSpaceInfo -> PathProvider PreCheck 输入契约
```

原始流程重点：

```text
ValetParkingStageParking::Process()
  -> IsReadyToFinishStage()
  -> destination_reached + standstill
  -> sys_mode 决定 next_stage_ / FinishScenario()

SetParkingType()
  -> sys_command / sys_run_state / sys_warning_info
  -> planning_status.avp_status.parking_type

ROI / PreCheck
  -> Frame/OpenSpaceInfo 承载目标、障碍、边界、轮挡和车辆状态
  -> OpenSpaceCollisionCheck / PathProvider::PreCheck 提前拦截错误问题
```

本批次当前实现：

```text
StageFinishRuntimeState
  -> consecutive_ready_frames
  -> finish_required_frames=2
  -> stage_finish_state=WAITING/HOLDING/READY

FunctionManagerProjection
  -> function_manager_sys_mode=RPA
  -> function_manager_sys_command=PARKINCONTROL/FORWARDCONTROL/...
  -> function_manager_sys_run_state=PARKSTART/PARKING/PAUSE/STRAIGHTBRAKE/...
  -> function_manager_sys_warning_info=NO_WARNING/SYSTEM_PAUSE_0x0B
  -> function_manager_parking_type=PARKING_IN/DIRECT_FORWARD/NOSTATE/...

ROI_DECIDER ok
  -> fine_tuned / slot_inner_fs_valid / scenario_difficulty
  -> ROI wall / virtual obstacle segment diagnostics

PATH_PROVIDER_PRECHECK ok
  -> roi_segments / external_segments
  -> near_start_segments / near_end_segments
  -> vehicle_has_state
  -> wheel_mask_contract=not_exposed_in_current_mvp
```

这些仍然是当前 DDS MVP 内的行为等价契约，不是把原始 `Frame/FunctionManager/HMI` 全量搬过来。

## BATCH-053_056 已减少的差异

| 原始流程节点 | 之前差异 | 本批次收敛 |
|---|---|---|
| `IsReadyToFinishStage()` | 只表达 finish 优先级，缺少连续帧和车辆静止状态 | 增加 `destination_reached && vehicle_standstill` 连续 2 帧状态机，并输出 `finish_ready/finish_consecutive_frames/stage_finish_state` |
| `SetParkingType()` / `FunctionManagerIn` | 当前临时 `ParkingCommand` 与原车 `sys_command/sys_run_state` 没有同名对照 | 增加 `FunctionManagerProjection`，在普通链、direct、pause/brake/finish、unsupported parking-out 分支输出原车命名投影 |
| `Frame/OpenSpaceInfo` 最小字段 | 只能看到 ROI/PATH_PROVIDER 成功，不能细看 ROI 建模字段 | ROI 成功日志补 `fine_tuned/slot_inner_fs_valid/scenario_difficulty/roi_wall_segments/virtual_obs_segments` |
| `PathProvider::PreCheck` / collision | 只验证 xy bounds、障碍数量和局部边界 | PreCheck 成功日志补 `roi_segments/external_segments/near_start_segments/near_end_segments/vehicle_has_state` |
| wheel mask | 容易被误认为已经完整接入 | 明确写入 `wheel_mask_contract=not_exposed_in_current_mvp`，作为后续真实 wheel mask 接入点 |

## 仍未收敛的核心差异

- `parking_status`、`FunctionManagerProjection`、`stage_finish_state` 仍是 `replan_reason/estop.reason` 文本诊断，不是正式 DDS 字段。
- `next_stage_` 和 `FinishScenario()` 仍未形成真实状态机，`finish_ready=true` 只表示当前 Adapter 已满足轻量完成条件。
- `Frame/OpenSpaceInfo/PlanningContext` 仍是轻量替代，不是原始大框架。
- `OpenSpaceCollisionCheck` 和 wheel mask 仍未完整接入，当前只做前置几何保护和缺口诊断。
- `OpenSpacePathSmoother/NLP` 仍因依赖未闭包而未进入产品链路。
- `PARKING_OUT_*` 仍是 `unsupported_in_mvp`，不是出库算法。
