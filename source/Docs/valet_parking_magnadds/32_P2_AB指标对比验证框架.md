# P2 A/B 指标对比验证框架

- 日期：2026-08-01
- 状态：框架就绪，待运行环境执行

## 目的

对比 `ENABLE_NLP_SMOOTHER=OFF`（ILQR 仅）vs `ENABLE_NLP_SMOOTHER=ON`（ILQR + NLP smoother）的规划质量差异，决定默认策略。

## 编译矩阵

| 场景 | 编译命令（Docker 内） | 说明 |
|---|---|---|
| A（基线） | `./build_app.sh --build=x86 --mode=release --module=valet_parking` | ILQR only |
| B（NLP） | `./build_app.sh --build=x86 --mode=release --module=valet_parking --features=ENABLE_NLP_SMOOTHER` | ILQR + NLP |

> m57 对应命令：替换 `--build=x86` 为 `--build=m57`

## 运行方式

```bash
# 终端 1：启动 libvalet_parking.so runner
./out/x86/app/valet_parking_runner

# 终端 2：发送测试车位
./out/x86/app/selected_slot_mock_publisher

# 终端 3：订阅输出轨迹
./out/x86/app/planning_trajectory_mock_subscriber
```

## 判定规则

1. 如果 B 的轨迹可行率 ≥ A 且时延不显著退化（≤10%），则建议默认启用 NLP
2. 如果 B 的轨迹质量（平滑度/终点偏差）显著优于 A，即使时延略高也建议启用
3. 如果 B 导致 fallback 率上升或碰撞，则保持 A 为默认

## 回滚方案

若 B 场景指标不达标：
```bash
# 重新编译（关闭 NLP）
./build_app.sh --build=x86 --mode=release --module=valet_parking
```
行为退回 Phase 2 基线，无任何残留影响。
